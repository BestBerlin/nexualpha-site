# Coin pages: data and daily refresh

`/coins` and `/coins/<slug>` ("Where to buy <coin>") render from files generated by
`scripts/build-coin-availability.mjs`. The site build never calls the network; refreshing the data means re-running the
script and shipping the result.

## What the script reads (public endpoints, no API keys)

| Data | Source |
| --- | --- |
| Coin universe (top 200 by market cap), price, 24h change, market cap | CoinGecko `/coins/markets` |
| Categories (layer 1, meme, stablecoin, …) and the excluded derivative receipts (wrapped, bridged, staked, tokenized funds) | CoinGecko `/coins/markets?category=…` |
| Token contract networks | CoinGecko `/coins/list?include_platform=true`, `/asset_platforms` |
| Spot pairs, USDT/USDC perpetuals | OKX, Binance, Bitget, Bybit, Gate, MEXC, HTX, Kraken public instrument lists |
| Ticker-collision check | each venue's public spot tickers: a venue whose USD price for the ticker is >50% away from the coin's price lists a different token and is not counted |
| Deposit networks | Bitget `/api/v2/spot/public/coins`, Gate `/api/v4/spot/currencies`, HTX `/v2/reference/currencies` (the others need an API key, so the table says "See the deposit page") |
| Descriptions | our own text, `content-source/coins/descriptions/*.json` (11 locales) |
| Template copy | `content-source/coins/ui/<locale>.json` |

Outputs: `public/intel/coins.json` (full snapshot, also served at `/intel/coins.json`), `src/data/coins-data.generated.js`,
`src/data/coins-links.generated.js`, `src/data/coins-venue-links.generated.js`, `src/data/coins-copy.js`,
`src/data/coin-content-<locale>.js`.

## Commands

```sh
cd pilot-01-prototype
node scripts/build-coin-availability.mjs                  # full refresh (~10 min: CoinGecko free tier is rate limited)
node scripts/build-coin-availability.mjs --reuse-universe # keep coin list/prices, refresh exchange listings (~1 min)
node scripts/build-coin-availability.mjs --offline        # rebuild the modules from coins.json + content-source only
```

A venue that does not answer keeps its previous listing (marked `stale` in coins.json); the run fails only when CoinGecko is
unreachable. The script uses Node 20 built-ins only, so it also runs on the BaoTa host (`node:20-bookworm-slim`).

## Daily refresh (to be switched on by the lead)

1. Once a day (e.g. 03:20 UTC) on the build machine or a scheduled CI job:
   `node scripts/build-coin-availability.mjs && node --test tests/coins.test.mjs`.
2. If `git status` shows changes under `public/intel/coins.json` or `src/data/coin*`, commit them on a branch and open a
   PR (the coin test checks counts, the no-fine-print rule and sitemap consistency).
3. Merge and deploy through the normal "Deploy to production" workflow; then `node scripts/search-engines.mjs submit`
   (sitemap-coins.xml is in the sitemap index).

After load, a coin page asks one exchange that lists the coin (OKX, Bitget, Binance or Gate public ticker, CORS-enabled,
no key) for the live USDT/USDC price and shows it with its source; the server HTML and the hub show the snapshot price with
its UTC time, so a stale snapshot is always labelled.

## Indexing rules

- `/coins` is indexable in en, es, pt-BR, tr, vi, id, zh-Hans, ja, ko, fr, de.
- `/coins/<slug>` is indexable in those locales when at least one covered exchange lists the coin and our description
  exists in that locale. Otherwise `noindex,follow` (the page still renders, with similar listed coins).
- Other UI locales (zh-Hant, ru, ar, it, ur, uk) render the page with English descriptions as `noindex,follow`.
- A new coin entering the top 200 gets a page right away (noindex until its descriptions are added to
  `content-source/coins/descriptions/`).
